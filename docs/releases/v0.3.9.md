# Nam-tor v0.3.9 — first-run reliability fixes

> **Experimental preview.** Do not enable on security-sensitive PAM services.
> This release does not establish production biometric accuracy, spoof
> resistance, suspend/resume reliability, or cross-hardware TPM readiness.
> See [`docs/evidence/status-audit.md`](../evidence/status-audit.md).

## Fixes

- **D-Bus activation (#29):** desktop clients now activate the same hardened
  systemd service as PAM socket clients. The service receives the pre-bound
  `root:namtor-auth` socket; no directory permissions or daemon privileges are
  widened.
- **Emitter lifecycle (#30):** bounded illumination windows recover after their
  cooldown instead of leaving long-running enrollment sessions permanently
  dark. The maximum on-time remains a safety limit, not a heartbeat timeout.
- **Worker lifecycle (#31):** worker IPC descriptor inheritance and parent-death
  handling prevent workers surviving a failed or abruptly terminated daemon.
- **Settings switches (#32):** profile and PAM-service switches use valid GTK
  widget parenting while retaining callbacks and authoritative-state rollback.
- **Arch first install (#33):** system identities are established before D-Bus
  policy files become visible during extraction. Fresh-boot broker validation
  remains outstanding; this is not a claim that it was performed.
- **Test isolation (#35):** the NoFetch test uses its own temporary cache,
  avoiding collisions with unrelated files in `/tmp`.

## Upgrade and limitations

Install the matching core and UI packages through your package manager. PAM
services remain off on a fresh install; setup stays in the Settings app. This
release does not change existing biometric templates or model weights.

The release workflow builds and exercises Arch x86_64, Debian 13 amd64 and
Fedora 41 x86_64 packages. The package-matrix asset records this tag's actual
results; do not substitute older evidence or treat static package tests as a
real hardware enrollment test. There is no aarch64 release-matrix cell.

Hardware enrollment and fresh-boot checks were not run during this fix session.
Dependency audit warnings are tracked separately in #37; the current policy
permits warnings and does not equate an exit-zero audit with production
readiness. Adjacent installation/diagnostic follow-ups are tracked in #36.

**TPM2 packaging limitation (#38):** release builds do not currently enable
the optional `namtor-store/tpm2` feature. Existing software-backed keys are
not automatically migrated. A TPM device being present does not imply that
this build sealed the key with it; use the reported storage protection mode.
Do not delete a key to clear a warning, since existing templates depend on it.

Checksums and an SBOM are generated by the release workflow. Check the actual
assets for a GPG signature: signing depends on the owner's configured secret,
and a passing local signature-machinery test is not a signature of these
packages. No SLSA provenance claim is made by these notes.
