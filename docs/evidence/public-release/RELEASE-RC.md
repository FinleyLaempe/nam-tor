# Nam-tor — Release Candidate (RC) Index

> **Experimental preview.** This is an evidence-complete release candidate,
> not a production release. No G1-G5 production gate has passed with measured
> evidence. The RC remains labelled **experimental preview until G3/G4 pass**.
> Do not enable Nam-tor on security-sensitive PAM services.

This index traces every release claim to immutable evidence in
`docs/evidence/public-release/`. It was generated by
[`packaging/tests/test_release_ledger.sh`](../../packaging/tests/test_release_ledger.sh)
(Task 32), which reconciles the gate ledger from evidence, verifies artifact
hashes/SBOM/package matrices, lists owner-gated hardware/data claims as
WITHHELD, and refuses to cut an RC if any structural/turnkey gate fails. The
test is mutation-checked: deleting or tampering one evidence file forces RC
generation failure (see `32-rc-mutation.json`).

- **Audit date:** 2026-08-09
- **Baseline commit:** `5e3727edf5f966a8aa0df3f060aeb93be4bce535`

## 5. Installation UX claim (tested package behavior)

The public installation claim in [`README.md`](../../README.md) exactly matches
tested package behavior:

- **Setup is Settings-only.** No CLI or root shell is needed. The Settings app
  (GNOME or KDE) drives enrollment and PAM-service enablement through the
  D-Bus `org.namtor.Manager2` interface (polkit-authorized).
- **PAM services are off by default** at install time. No PAM config is edited
  during package installation. Verified by
  [`13-install-default-off.json`](13-install-default-off.json).
- **Per-service opt-in.** Each PAM service is toggled independently; unsupported
  services (e.g. `sshd`) are refused.
- **TPM warning.** If no TPM2 is present, storage falls back to a software key
  and the Settings app shows a visible warning (never silent).
- **Bundled models.** Three permissively-licensed ONNX models ship in the
  package; no network access is needed at install time.

The doc audit ([`26-doc-audit.json`](26-doc-audit.json)) verifies the README
carries the experimental-preview warning, the WITHHELD gates table, and the
Settings-only setup instructions, and that no stale claim remains.

## 6. RC label

**This RC remains labelled "experimental preview" until G3/G4 pass.** No G1-G5
production gate is claimed as passed. Biometric accuracy (FAR/FRR), spoof
resistance (APCER/BPCER), TPM2 cross-hardware sealing, suspend/resume
reliability, and score normalisation are all unmeasured or withheld. Face
authentication is a convenience factor, not a hardening measure.

The RC is cut only because every structural/turnkey gate passes with traced
evidence and every unresolved production gate is explicitly WITHHELD. If a
required hardware QA gate is missing, it blocks the RC rather than being
converted to an approval.
