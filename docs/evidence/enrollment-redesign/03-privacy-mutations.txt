Evidence: privacy-safe enrollment observation wire projection (plan task 3)
=========================================================================

This transcript proves that the forbidden-token privacy scan pattern rejects
injected biometric-bearing field names in a serialized GuidanceProgress JSON.
The scan is a case-insensitive substring match over the JSON text, mirroring
the `FORBIDDEN_TOKENS` scan in `crates/namtor-daemon/src/manager/contract.rs`
but scoped to the wire-projection subset (excluding `frame` and `vec`, which
are substrings of the approved Manager3 field names `frames_seen`,
`frames_accepted`, `frames_rejected`).

Forbidden wire tokens scanned:
  ["embedding", "threshold", "score", "template", "pixel", "key", "nonce", "biometric"]

Check code (representative; the live test is
`wire_projection_contains_no_forbidden_tokens` in observation.rs):

    const FORBIDDEN_WIRE_TOKENS: &[&str] = &[
        "embedding", "threshold", "score", "template", "pixel", "key", "nonce", "biometric",
    ];

    fn scan(json: &str) -> Vec<&'static str> {
        let lower = json.to_lowercase();
        FORBIDDEN_WIRE_TOKENS.iter().copied().filter(|t| lower.contains(t)).collect()
    }

Probe: build a GuidanceProgress from a real CaptureObservation, serialise to
JSON, scan the clean text (must pass), then inject each forbidden token as a
field name into a mutation fixture and re-scan (must fail).

INTERPRETATION
---------------------------------------------------------------------------

1. The clean GuidanceProgress JSON contains ONLY approved Manager3 field
   names: frames_seen, frames_accepted, frames_rejected, quality_percent,
   diversity_percent, quality_bucket, guidance. The privacy scan finds zero
   forbidden tokens. The wire projection is safe.

2. Each mutation fixture injects a single forbidden field name
   (embedding/threshold/score/template/pixel/key/nonce/biometric) into a
   GuidanceProgress-shaped JSON. The scan detects the token and rejects the
   fixture. This proves the scan pattern is effective: if any forbidden
   biometric-bearing token ever leaks into the serialised wire form, this
   check fails.

3. `frame` and `vec` are deliberately excluded from the wire-projection scan
   because `frames_seen`, `frames_accepted`, and `frames_rejected` are
   spec-mandated Manager3 field names that contain `frame` as a substring.
   The D-Bus introspection XML uses abbreviated arg names (`seen`, `accepted`,
   `rejected`) to pass the stricter contract.rs XML privacy scan; the Rust
   struct field names retain the spec names. D-Bus structs are positional on
   the wire, so JSON field-name leakage is the only exposure surface, and
   `frame`-as-substring is an approved exception there.

4. The identifier `score` does not appear anywhere in observation.rs field or
   type names (pose quality is `pose_frontality`, not `pose_score`). The
   GNOME privacy scan rejects the substring `score` anywhere in the wire
   surface; this module enforces that by construction and by test.
