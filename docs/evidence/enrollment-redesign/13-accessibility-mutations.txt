PART B — Test 9 mutation: blank an accessible name
================================================================

The mutation_unlabeled_button_rejected test blanks the save_button
accessible name in an in-memory copy of the ACTIONABLE_WIDGETS registry
and asserts the scan logic flags it.

Test logic (tests/shell_navigation.rs):
  let mut mutated = ACTIONABLE_WIDGETS.to_vec();
  let save_idx = mutated.iter().position(|(_, w, _)| *w == "save_button").expect(...);
  mutated[save_idx] = ("navigation.rs", "save_button", "");
  let unlabeled = mutated.iter().filter(|(_, _, name)| name.is_empty())...;
  assert!(!unlabeled.is_empty());
  assert!(unlabeled.contains(&"navigation.rs"));

Result: PASS — the blanked name is flagged as unlabeled.

Cross-check: if all_actionable_widgets_have_accessible_names were run
against the mutated registry, it would fail:
  assert!(!name.is_empty(), "actionable widget navigation.rs:save_button has no accessible name");
  --> panicked: actionable widget navigation.rs:save_button has no accessible name

PART C — Test 10 mutation: inject a forbidden word into a UI string
================================================================

The mutation_forbidden_word_rejected test takes a clean baseline string
("Save the enrolled profile") and injects each forbidden substring, then
asserts forbidden_words_in_ui_string catches every one.

Test logic (tests/privacy_scan.rs):
  let baseline = "Save the enrolled profile";
  assert!(forbidden_words_in_ui_string(baseline).is_empty(), "baseline clean");
  for forbidden in FORBIDDEN_SUBSTRINGS {
      let poisoned = format!("{baseline} ({forbidden} leaked)");
      let hits = forbidden_words_in_ui_string(&poisoned);
      assert!(hits.contains(forbidden), "forbidden word '{forbidden}' NOT caught");
  }

Forbidden substrings scanned (16 total):
  vector, embedding, template, landmark, descriptor,
  raw_frame, frame_data, frame_buf, frame_pixel, frame_raw,
  score, threshold, biometric, key, nonce, pixel

Result: PASS — all 16 forbidden substrings are caught when injected.

Cross-check: the no_biometric_wording_in_ui_strings test scans the
UI_STRING_REGISTRY (192 entries across 8 source files). Before the
wording fixes in this task, the scan failed on:
  system_status.rs: "Software Key (fallback)" -> ["key"]
  navigation.rs:    "Only mathematical embeddings are saved." -> ["embedding"]
  enrollment.rs:    "Your biometric templates are encrypted..." -> ["template", "biometric"]

After rewording (see 13-accessibility.json forbidden_wording_fixed),
the registry is clean and the test passes.
